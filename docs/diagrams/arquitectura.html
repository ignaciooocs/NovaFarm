Backend module boundaries

One NestJS process, not several services. Every controller sits behind the same tenant guard, and modules only ever reach each other through a published service method — never by importing another module's raw Mongoose model.

FarmScopeGuard + @CurrentFarm() — applied to every controller below. Tenant scoping is enforced once, structurally, not re-derived per query.

AuthModule · planned

Login, JWT issuance, password hashing (library not chosen yet). Calls into UsersService to verify credentials — the only module allowed to touch User.passwordHash.

FarmsModule

Owns the tenant. Exports FarmsService — create a farm, validate an invitationCode. No other module reads its schema directly.

UsersModule

Owns authenticated users. Exports UsersService. Consumed by AuthModule only.

HarvestersModule

Owns the per-farm worker catalog. Exports HarvestersService.findActiveByFarm(). Consumed by HarvesterWorkdayModule and HarvestEntriesModule.

FruitsModule

Owns the fruit catalog. Exports FruitsService. Consumed by WorkdaysModule to validate fruitId on open.

MeasurementUnitsModule

Owns containers/weighing methods and their kgFactor. Exports MeasurementUnitsService. Consumed by WorkdaysModule and HarvestEntriesModule.

WorkdaysModule

Owns the day's fruit, default unit, and open/closed state. Exports WorkdaysService. Calls into FruitsService and MeasurementUnitsService; consumed by HarvesterWorkdayModule and HarvestEntriesModule.

HarvesterWorkdayModule

Owns the day's roster. Exports HarvesterWorkdayService. Calls into HarvestersService and WorkdaysService.

HarvestEntriesModule

Owns each delivery record — the highest write volume in the system. Exports HarvestEntriesService. Calls into HarvestersService, WorkdaysService, MeasurementUnitsService.

Offline-sync flow

The one part of this system that doesn't get to be a normal always-online API. From a tap in the field to a durably-synced row.

1

Capture locally

"Anotar" (+1 / +2 / +5) writes straight to SQLite. Sub-100ms, zero network dependency — the interaction can't wait on a request that might not have anywhere to go (RNF-01).

SQLite write
2

Queue grows offline

Nothing blocks on connectivity. The only feedback is a pending-annotations count — "15 anotaciones pendientes de subir" (RF-04.2).

3

Recorder triggers sync

Explicit tap on "Sincronizar Jornada." Never automatic, never on a timer (RF-04.3).

4

Chunked, idempotent upload

~500 entries per request, each tagged with a client-generated clientEntryId. The server upserts on {workdayId, clientEntryId} — a chunk retried after a dropped connection can't create a duplicate.

clientEntryId (new field)
5

Per-item acknowledgment

The response reports created / already-synced / rejected+reason per row — not all-or-nothing. A row against a CLOSED workday is rejected with a specific error the app surfaces to the recorder, not silently dropped or recomputed.

6

Local state reconciled

Synced rows are marked syncedOffline: true; rejected rows stay queued for the recorder to see and resolve.

Security & open items

Decisions made now, stated plainly — and the gaps that shouldn't be discovered mid-integration instead of here.

Atlas stays open, on purpose

"Access from anywhere" + enforced TLS + a least-privilege DB user is the accepted MVP posture — PrivateLink needs an M10+ cluster this project doesn't have yet. Not an oversight; a documented tradeoff.

nationalId is opt-in, like passwordHash

Worker PII should never ride along on a default roster query — same select: false treatment passwordHash already gets on users.

Password hashing — not picked yet

No argon2 or bcrypt installed. Needs deciding before AuthModule work starts, not mid-way through it.

No rate limiting yet

/auth/login is the one endpoint doing password auth over the open internet on a PII-bearing, multi-tenant system — @nestjs/throttler before launch.

Decimal128 doesn't serialize for free

unitCount, totalKg, kgFactor are BSON Decimal128 — without an explicit @Transform on response DTOs, the client receives {"$numberDecimal":"12.34"}, not a plain value.

No global ValidationPipe yet

main.ts is still just create() + listen(). "DTO-validated" is the target, not the current state.

No health check

Both Railway and Render gate deploy/restart on one. Without /health, a broken deploy can be marked healthy.

No migration tool decided

Mongoose is schemaless at the DB level, but the clientEntryId addition above is itself a schema change — worth deciding a tool (e.g. migrate-mongo) before real data exists.
